1. Introduction                                      *keymap-forensics-intro*

keymap-forensics answers "who bound this key?" from a running Neovim.
It reads |maparg()|'s dict form, resolves the mapping's script id to a
filename via |getscriptinfo()|, and chases one hop of `<Plug>`
indirection to reveal the underlying command.

Complements plug-audit (compile-time / static) with runtime data.

==============================================================================
2. Commands                                       *keymap-forensics-commands*

------------------------------------------------------------------------------
2.1. :WhyKey                                                        *:WhyKey*

>
    :WhyKey {lhs}
    :WhyKey {mode} {lhs}
<
Look up the mapping for {lhs} in {mode} (default: `n`) and print a
formatted attribution to |:messages|. Valid modes: `n`, `i`, `v`, `x`,
`o`, `c`, `t`.

Prints `no mapping` when {lhs} has no mapping in {mode}.

------------------------------------------------------------------------------
2.2. :WhyKeyConflicts                                       *:WhyKeyConflicts*

>
    :WhyKeyConflicts
<
Report every keymap prefix collision across standard modes. A
collision is a mapping whose lhs is a strict prefix of another
mapping in the same mode — pressing the prefix triggers it
immediately (or after 'timeoutlen'), blocking the longer sequences.

Namespace-style prefixes that are themselves unbound (Vim's `g`
group, for example) are excluded. Only mappings the user has actually
bound show up as shadowing prefixes.

Example: >
    Prefix conflicts (n mode):
      <leader>f  blocks 2 longer sequence(s):
        <leader>f    :Files<CR>              (config/keymaps.lua:12)
        <leader>ff   :Telescope find_files   (plugins/telescope.lua:42)
        <leader>fg   :Telescope live_grep    (plugins/telescope.lua:43)

    Prefix conflicts (i mode):
      none

    Scanned 187 mappings across 7 modes.
<

==============================================================================
3. Output shape                                     *keymap-forensics-output*

>
    <lhs> (<mode> mode)
      bound to: <rhs, or <Plug>(...) → <target>, or <lua callback>>
      source:   <file>:<line>       (omitted when script id is 0)
      desc:     <mapping desc>      (omitted when unset)
      scope:    buffer-local        (omitted for global mappings)
<
Example: >
    :WhyKey <leader>ff
    <leader>ff (n mode)
      bound to: <Plug>(TelescopeFindFiles) → <cmd>Telescope find_files<CR>
      source:   lua/plugins/telescope.lua:42
      desc:     Find files
<

==============================================================================
4. API                                                 *keymap-forensics-api*

Submodules (`require("keymap-forensics.<name>")`):

- `attribution` — `attribute(lhs, mode, deps?)` returns the record
                  shape shown above. Pure; injectable deps for tests.
- `conflicts`   — `find(deps?)` returns a per-mode prefix-collision
                  report. Pure; injectable deps for tests.
- `format`      — `render(record)` and `render_conflicts(report)`.
- `health`      — |:checkhealth| entry point.

Facade (`require("keymap-forensics")`):

- `why_key(lhs, mode?, deps?)`     — attribute + print. Returns the
                                      raw record so callers can pipe it.
- `why_key_conflicts(deps?)`       — scan + print. Returns the raw
                                      conflicts report.

==============================================================================
5. Health                                           *keymap-forensics-health*

Run `:checkhealth keymap-forensics` to verify:

- The plugin loaded and the detector permits execution.
- |getscriptinfo()| is available (Neovim 0.10+). Without it, `:WhyKey`
  still works but source paths fall back to "script id N".
